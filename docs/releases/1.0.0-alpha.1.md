# NolQu-L 1.0.0-alpha.1

First public Alpha for evaluation and continued development. Source and feature
contracts remain experimental; this is not a stable or security-qualified
release. `VERSION` is `1.0.0-alpha.1`, `CHANNEL` is `dev`, and the tag is
`v1.0.0-alpha.1`. Main and Dev identify the same qualified source snapshot.
Stable remains reserved for future RC/final work.

## Available

- Canonical `nql` / `nolqul` and `nqlc` / `nolqulc` entry points, `.nql` projects
  and the explicit experimental `--backend canonical` path. The default NASM
  path remains Reference Compiler R0; it is not a canonical bootstrap stage.
- Traceable x86_64 Linux machine foundation, Stage 0, B0 and Core components.
  C0.32 frontend/backend support checked i64 arithmetic, lexical scope,
  control flow, functions/calls, byte/stream operations and explicit bounded
  native access. The separate C0.25 emitter and its evidence remain preserved.
- Predecessor rebuilds and complete component-generation comparisons, canonical
  CLI/install tests, finite malformed-input assurance and independent defined-
  program differential checks. These are bounded engineering evidence, not a
  proof of absence of compiler bugs.
- An offline host bundle with pinned compiler components and optional
  `run --require-native-termux --differential`: 48 valid programs on two runtime
  profiles and two sensitivity controls, retaining exact results and failures.

## Downloads and verification

The source archive contains committed public source, documentation, tests and
canonical seed/pin files. Follow its README for installation and dependencies.
It is not a newly built general-purpose native compiler binary distribution.

The `termux-bundle` archive is optional host testing tooling. It requires Python
and, off x86_64, `qemu-x86_64`. Its compiler components still target x86_64 Linux;
its name does not imply a new AArch64 compiler backend or full Android target
qualification. Run the copied `android_smoke.py`, using a new result directory.
See `tests/security/README.md` in the source archive for commands and limits.

Check downloaded files with `sha256sum -c SHA256SUMS` in a directory containing
all four listed assets. BUILD-METADATA.json records source revision, compiler
identities, build environment and reproducibility scope. QUALIFICATION.json
contains the exact Main/Dev Linux gate receipts. The source and bundle archives
are each built twice and compared before publication; this is a same-environment
comparison. Checksums establish byte identity, not signer identity.

## Known limitations

- Full Compiler, formal self-hosting `nqlc` and Verified `nqlc` remain **NOT
  IMPLEMENTED**. Equal component generations do not promote those stages.
- General types, ownership, lifetimes, borrowing, modules and complete
  NolQu-L Safety remain unfinished. Unsafe invariants are explicit programmer
  obligations, not an automatic proof that arbitrary native effects are safe.
- The new offline differential profile is exercised by Linux/QEMU host controls.
  Actual untraced native Termux execution of this new profile is **NOT RUN** in
  the release session. Its native requirement fails closed in PRoot or an
  unconfirmed context. Native Termux qualification remains a separate task.
- Historical incident **C032-SIGNAL-01** remains **OPEN**: a frozen comparison
  backend previously received SIGKILL, and its original sender/cause was not
  retained. Later passes do not close it. Stable/security-qualified promotion
  remains blocked; no quarantine or OOM attribution is implied.
- Fuzzing is finite and deterministic, not coverage-guided. No sanitizer or
  dependency-advisory scan result is claimed by this release. Formal provenance
  attestation, artifact signing and SBOM are **NOT IMPLEMENTED**.

## Compatibility and support

No source, ABI, canonical seed or public CLI naming change is introduced by
release packaging. Older offline bundles retain ordinary smoke; the optional
extended profile needs the new bundle format. No deprecations or removals are
introduced here. Historical `1.0.2a1` version labels remain historical; Alpha 1
is the documented naming reset rather than a claim of numerical upgrade.

Lifecycle is **DEVELOPMENT**, with no invented support duration or stable
compatibility commitment. Published assets and this tag are immutable; later
corrections require a new release version.
