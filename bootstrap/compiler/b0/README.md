## C0.31 Explicit Compiler Profile

Compile mode accepts `--compiler-profile` before the input, after the input,
or after the complete `-o output` pair:

```text
b0.candidate --compiler-profile input.nql -o output
b0.candidate input.nql --compiler-profile -o output
b0.candidate input.nql -o output --compiler-profile
```

Duplicates, unknown options, use with `--lex`/`--parse`, and splitting `-o`
from its operand are rejected before writing output. Normal compilation retains
B0.7r's exact generated bytes, syntax, 16-local limit and successful intrinsic
semantics. In particular, writes remain statements, `input_read` returns the
actual count, arithmetic still wraps, and even an empty stream range requires
an offset naming a byte. This is not the C0 stream or arithmetic contract.

Profile expression programs and literal-write programs map 16,777,216 zeroed
bytes with anonymous/private Linux `mmap`, read/write permissions and no execute
permission. A fast literal return needs no mapping. Bounds are checked before
forming pointers: byte indices are 0..16,777,215 and stream counts must fit the
remaining range. Constant errors retain B0-CG-008 with the selected bound;
dynamic bounds errors exit 70. No 16 MiB stack allocation is emitted.

The runtime reserves R13 for acquired state and R14 for the mapping base, with
R12/RBX holding cleanup/diagnostic continuations and R15 recording broken stderr.
A failed diagnostic or `error_write` marks stderr unusable before cleanup. If
the subsequent `munmap` also fails, the runtime exits 74 without another fd-2
write or a second unmap attempt. The combined-failure test covers negative and
zero write results using actual guest syscall-result injection, not native
kernel-failure claims. All 16 RBP-relative locals
remain available. Generated helpers use jumps, so expression-stack depth adds
no call-alignment requirement. R8 carries the exit status across teardown;
syscall-clobbered RCX/R11 never carry ownership or pending return state.

Reads retry EINTR while retaining short-read/EOF semantics. Both stream writes,
literal writes and diagnostics retry EINTR and finish partial writes. Every
handled exit after acquisition attempts one `munmap`. Diagnostic failure still
cleans up and exits 74 without recursively reporting stderr failure. Mapping or
unmapping failure reports a fixed B0 runtime cause/remedy and exits 74; a failed
unmap is not retried. Fatal signals rely on process reclamation.

The canonical source remains manually authored Stage0 machine bytes and labels.
Fixed-size hooks retain text at file offset 0x1000, rodata at 0x5000 and BSS at
virtual address 0x406000. The extension occupies unused RX padding and must not
cross rodata. The candidate is a sectionless ELF; discarded linker metadata
was never loaded. The reference is independently maintained NASM flat assembly
with matching explicit headers, built using `nasm -f bin` solely for whole-file
audit. Neither the reference nor a host semantic patcher builds the candidate.

`tests/bootstrap/test_b0_compiler_profile.py` accepts an explicit `B0_COMPILER`
candidate path and compares default fixture bytes, statuses and streams with
the verified frozen predecessor. It also exercises the actual frozen C0.30
frontend/backend sources. QEMU debugger tests verify instructions before fault
injection and perform real shortened writes. Those tests establish bounded
guest behavior, not a native-kernel signal or general leak proof.

Candidate validation used a separate provisional installation before promotion.
The authoritative materializer now reconstructs the reviewed profile seed from
the installed machine source and matching pin. Final installation verification
passed; no old pin or environment override bypass is used.

## B0.2 Target

B0.2 adds a bounded lexer mode:

```text
b0.seed --lex <input.nql>
```

The lexer recognizes Core-0 keywords, identifiers, integer literals, string
literals, punctuation, `==`, `!=`, `<`, `<=`, ASCII whitespace, LF, CRLF,
`//` comments, and `#` bootstrap comments. Invalid characters and unterminated
strings fail before any token dump is written.

This is still not enough to promote `bootstrap-compiler` in
`bootstrap/manifest.tsv`; B0.6 owns manifest promotion.

## B0.3 Target

B0.3 adds a bounded parser mode:

```text
b0.seed --parse <input.nql>
```

The parser accepts Core-0 function declarations, `fn main()`, blocks, `let`,
assignment to an existing local, `return`, intrinsic-style call statements,
`if/else`, `while`, grouped expressions, and simple binary expression chains
over identifiers, integers, strings, and calls. A successful parse writes
`PARSE OK`.

This is still not enough to promote `bootstrap-compiler`; B0.6 owns manifest
promotion after all B0 gates are green.

## B0.7 Target

B0.7 removes whole-source identity as a prerequisite for the subset needed by
C0. The completed slices lower these source shapes semantically:

```text
fn main() { return <u32> }
fn main() { write(<string>); return <u32> }
fn main() { let <name> = <integer-expr>; return <integer-expr> }
fn main() { if <integer-expr> { return <integer-expr> } else { return <integer-expr> } }
fn main() { let <name> = <integer-expr>; while <integer-expr> { <name> = <integer-expr> } return <integer-expr> }
fn main() { byte_store(<integer-expr>, <integer-expr>); return byte_load(<integer-expr>) }
```

Whitespace, comments, optional semicolons, integer values, string contents,
and supported escapes are read from source. Generated ELF headers, write
lengths, message bytes, and exit immediates are derived from those values.
Decoded strings are bounded to 2,048 bytes; exceeding that limit produces
`B0-CG-005` without creating output.

Integer programs use up to 16 local slots in a fixed 128-byte local region.
`let` declares a slot and assignment mutates an existing slot; assignment to
an unknown local fails with `B0-CG-007` at its actual source path, line, and
column. B0 emits x86_64 instructions for
literals, local loads/stores, parentheses, `*`, `/`, `+`, `-`, `<`, `<=`,
`==`, and `!=`. It emits and patches deterministic `rel32` conditional
branches for both true and false `if/else` paths. Simple `while` bodies use a
conditional exit branch and a real backward `rel32` jump. Constant metadata is
discarded after mutation and retained otherwise only for diagnostics such as
division by zero and the signed `INT64_MIN / -1` overflow case; the executable
still evaluates the generated instructions. Tests cover sequential loops,
multiple mutated slots, and metadata invalidation after assignment.

`byte_store(index, value)` and `byte_load(index)` use a separate zero-initialized
65,536-byte stack region. Store keeps the low eight bits; load zero-extends one
byte to an integer. Constant indices outside `0..65535` fail at the actual
source location with `B0-CG-008`. Dynamic indices use an unsigned machine-code
guard. Every guard targets one shared runtime handler that writes
`B0 runtime: byte-memory index out of bounds` to stderr and exits with status
70. Tests cover dynamic loop access, byte truncation, zero initialization, the
maximum valid index without overlapping the sixteenth local slot, deterministic
output, compile-time bounds failure, old output preservation, and runtime bounds
failure from both load and store guards. `byte_load` is treated as an intrinsic
only when followed by a call; a local with that name remains a normal binding.
Malformed `byte_store` syntax is rejected before constant bounds diagnostics.
The generated executable contains exactly one shared runtime handler regardless
of the number of byte-memory accesses.

`input_read(offset, count)` performs one raw `read` from fd 0 into byte-memory
and returns the byte count, including zero at EOF. `output_write(offset, count)`
writes the complete byte range to fd 1 and retries short writes. Both operations
accept dynamic ranges, share the unsigned byte-memory bounds handler, and emit
source-located `B0-CG-008` diagnostics for statically invalid ranges. Runtime
read/write failures produce a specific stderr diagnostic and exit status 74.
Per-invocation parse metadata keeps nested `input_read` calls from overwriting
the outer call's constant-range proof. Generated programs install `SIG_IGN` for
`SIGPIPE` with `rt_sigaction`; setup failure has a dedicated diagnostic, while a
broken pipe reaches the normal output error handler instead of silently exiting
with signal status 141.

`error_write(offset, count)` uses the same bounded byte-memory range contract
and complete-write loop for fd 2. A failed stderr write exits with status 74
without recursively attempting another diagnostic. This final bridge lets a
B0-built compiler keep artifacts on stdout and source diagnostics on stderr.

Canonical bootstrap I/O is stream-based: generated C0 reads source from fd 0
and writes its artifact to fd 1. Its materializer owns file paths, temporary
files, hash verification, and atomic rename. Tests prove binary byte parity at
a nonzero offset, EOF behavior, deterministic codegen, nested constant
validation, constant/dynamic/negative bounds, the final valid byte and full
65,536-byte range, call-position binding, multiple output patches, malformed
calls, closed-fd failures, and broken pipes. B0.7r is therefore `PASS`; C0 must
be implemented semantically rather than selected as a canned binary. C0.1
through C0.25 satisfy that handoff. C0.19 and C0.20 remain inside B0.7p;
C0.21 triggered the measured B0.7q output-only bridge. C0.22 changes only the
milestone header and adds a C0-compiled auxiliary tokenizer. C0.23 grows the
source to 313,990 bytes and its artifact to 545,270 bytes for bounded ASCII
classification. C0.24 grows the source to 327,359 bytes and requires the
measured B0.7r patch-only bridge; its 568,889-byte artifact remains below the
existing output cap. C0.25 changes only C0's internal table layout and canonical
identity while keeping the same source/artifact sizes and remaining inside all
B0.7r bounds. Further B0
expansion requires another concrete predecessor limit, while language growth
remains in C0.
