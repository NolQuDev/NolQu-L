# NolQu-L Stage 0

Stage 0 is a bounded, two-pass symbolic flat-binary emitter for x86_64 Linux.
It is intentionally smaller than a language compiler. Its purpose is to turn
an auditable machine-oriented source unit into the executable bytes of the
NolQu-L Bootstrap Compiler.

## Canonical Construction

The canonical Stage 0 executable is `x86_64-linux/stage0.seed`. Its bytes are
declared by `stage0.hex` and reconstructed by the Machine-Level Foundation:

```text
hex0.seed < stage0.hex > stage0.seed
```

`materialize.sh` performs that operation through a temporary file, verifies
`stage0.sha256`, marks the result executable, and renames it into place. Bash,
`sha256sum`, and QEMU on non-x86_64 hosts are orchestration or verification
tools. They do not parse Stage 0 source and are not semantic compiler stages.

`stage0.reference.asm` is a non-canonical audit aid. NASM parity can expose an
incorrect byte manifest, but NASM is never an input to the canonical build.

## Source Format

Stage 0 reads source from stdin and writes raw bytes to stdout. It accepts no
command-line arguments. Source consists of these items:

| Form | Meaning |
| --- | --- |
| `00` through `ff` | emit one byte; hexadecimal is case-insensitive |
| `:name` | define `name` at the current output offset |
| `@name` | emit signed little-endian `rel32` to `name` |
| `&name` | emit little-endian `u64(0x400000 + offset(name))` |
| `$name` | emit little-endian `u64(offset(name))` |
| `# ...` | ignore through LF, CR, or end of input |

Hexadecimal byte pairs may be contiguous. Symbolic items must end at
whitespace, a comment, or end of input. Symbols are case-sensitive and match:

```text
[A-Za-z_][A-Za-z0-9_]*
```

For a relative field beginning at output offset `P`, Stage 0 writes:

```text
offset(name) - (P + 4)
```

The `$name` form exists so ELF sizes and file offsets can be derived from an
end label. The `&name` form exists for addresses in the fixed bootstrap ELF
image. Stage 0 has no expression evaluator, object format, relocation table,
linker, instruction names, or hidden target abstraction.

## Execution Model

Stage 0 performs two complete passes before writing stdout:

1. validate all syntax, record labels, and compute output size;
2. emit bytes and resolve every reference.

Forward and backward references are therefore deterministic. Invalid syntax,
duplicate labels, undefined labels, and limit failures produce no stdout.
Diagnostics report the zero-based input byte offset when a source token is at
fault.

The executable uses only raw x86_64 Linux syscalls. It maps three bounded
read/write regions and unmaps all three on normal and handled error exits:

| Region | Limit |
| --- | ---: |
| source input | 4,194,304 bytes plus one overflow probe byte |
| generated output | 2,097,152 bytes |
| label records | 4,096 records of 24 bytes |

Symbol names are limited to 63 bytes. No file descriptor is opened, no code
mapping is writable, generated bytes are never executed in-process, and the
process stack is non-executable. Linux reclaims mappings on unhandled signal
termination.

## Exit And Output Contract

| Status | Meaning |
| --- | --- |
| `0` | source accepted and all output written |
| `1` | source, input-stream, output-stream, or usage error |
| `2` | internal invariant or allocation failure |

Writes retry `EINTR` and handle partial progress. The emitter buffers output,
but stdout itself cannot provide filesystem rename atomicity. A caller writing
an artifact must use a temporary file and rename after success, as
`materialize.sh` does.

## Qualification

`tests/bootstrap/stage0.sh` proves:

- reconstruction by `hex0.seed` and SHA-256 identity;
- parity with the optional reference assembly;
- self-reconstruction from `stage0.hex`;
- raw instruction emission and deterministic output;
- forward and backward `rel32`, image-address, and file-offset patches;
- generation and execution of a static ELF using control flow and
  RIP-relative memory access;
- bounded resource cleanup on success and source failure;
- diagnostics and non-zero status for malformed input and syscall failures.

Stage 0 does not implement NolQu-L Core. The next canonical artifact is the
NolQu-L Bootstrap Compiler source written in this Stage 0 format.
